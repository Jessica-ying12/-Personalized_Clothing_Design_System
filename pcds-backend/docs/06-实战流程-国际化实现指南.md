## 快速回答

**问题**: 如何在 Hammer-Admin 项目中实现接口响应的多语言支持？

**答案**:
1. 项目使用 `gettext` + `Babel` 实现国际化
2. 中间件自动解析请求头 `Accept-Language` 确定语言
3. 使用 `ResponseUtil.success/error` 返回响应时自动翻译
4. 翻译资源文件位于 `i18n/locale/` 目录

---

## 1. 技术方案概览

### 1.1 核心技术栈
- **库**: `gettext` + `Babel`
- **支持语言**: 中文、英文等
- **翻译方式**: 自动翻译（基于上下文）

### 1.2 工作流程

```
HTTP 请求
    ↓
中间件解析 Accept-Language
    ↓
确定当前语言并存入 contextvars
    ↓
业务处理
    ↓
ResponseUtil 响应封装
    ↓
自动调用 t(msg) 翻译消息
    ↓
返回对应语言的响应
```

---

## 2. 核心组件详解

### 2.1 中间件：语言解析与上下文管理

**文件位置**: `middlewares/locale_middleware.py`

**主要职责**:
1. 解析 HTTP 请求头中的 `Accept-Language` 字段
2. 确定当前请求的目标语言
3. 将语言信息存入 `contextvars` 上下文变量
4. 确保语言信息在整个请求生命周期内可用

**工作原理**:
```python
# 伪代码示例
async def locale_middleware(request, call_next):
    # 1. 从请求头获取语言
    language = request.headers.get('Accept-Language', 'zh-CN')

    # 2. 存入上下文
    locale_context.set(language)

    # 3. 继续处理请求
    response = await call_next(request)

    return response
```

**支持的语言格式**:
- `zh-CN`: 简体中文
- `en-US`: 英语
- `zh-TW`: 繁体中文

### 2.2 响应封装：自动翻译机制

**文件位置**: `utils/response_util.py`

**核心代码** (第 42 行附近):
```python
from i18n.translator import t

class ResponseUtil:
    @staticmethod
    def success(msg: str = "操作成功", data=None):
        return {
            "code": 200,
            "msg": t(msg),  # 关键：通过 t() 函数包裹消息
            "data": data
        }

    @staticmethod
    def error(msg: str = "操作失败", code: int = 500):
        return {
            "code": code,
            "msg": t(msg),  # 自动翻译错误消息
            "data": None
        }
```

**翻译函数 `t()` 的工作原理**:
1. 接收中文消息作为 `msgid`（消息标识）
2. 从 `contextvars` 获取当前请求的语言
3. 在翻译资源文件中查找对应的翻译
4. 返回翻译后的文本（如果没有找到，返回原文）

### 2.3 翻译资源文件

**文件位置**: `i18n/locale/`

**目录结构**:
```
i18n/
└── locale/
    ├── zh_CN/
    │   └── LC_MESSAGES/
    │       ├── messages.po   # 源文件（可编辑）
    │       └── messages.mo   # 编译文件（机器读取）
    ├── en_US/
    │   └── LC_MESSAGES/
    │       ├── messages.po
    │       └── messages.mo
    └── zh_TW/
        └── LC_MESSAGES/
            ├── messages.po
            └── messages.mo
```

**`.po` 文件示例**:
```po
# messages.po
msgid "操作成功"
msgstr "Operation successful"

msgid "操作失败"
msgstr "Operation failed"

msgid "参数错误"
msgstr "Invalid parameters"

msgid "用户不存在"
msgstr "User does not exist"
```

**`.mo` 文件**:
- 由 `.po` 文件编译生成
- 二进制格式，运行时快速读取
- 使用 `msgfmt` 或 Babel 命令编译

## 3. 使用指南

### 3.1 基本使用

**在 Controller 层返回响应**:
```python
from utils.response_util import ResponseUtil

@router.post("/user/add")
async def add_user(user_data: UserAddModel):
    # 业务逻辑处理
    try:
        result = await UserService.add_user(user_data)
        # 成功响应（自动翻译）
        return ResponseUtil.success(msg="操作成功", data=result)
    except Exception as e:
        # 错误响应（自动翻译）
        return ResponseUtil.error(msg="用户添加失败")
```

**前端请求示例**:
```javascript
// 请求中文响应
fetch('/api/user/add', {
  headers: {
    'Accept-Language': 'zh-CN'
  }
})

// 请求英文响应
fetch('/api/user/add', {
  headers: {
    'Accept-Language': 'en-US'
  }
})
```

### 3.2 自定义消息翻译

**步骤 1: 在业务代码中使用中文消息**
```python
# 直接使用中文，系统会自动翻译
return ResponseUtil.error(msg="该用户名已存在")
```

**步骤 2: 在 `.po` 文件中添加翻译**
```po
# i18n/locale/en_US/LC_MESSAGES/messages.po
msgid "该用户名已存在"
msgstr "This username already exists"
```

**步骤 3: 编译 `.po` 文件为 `.mo`**
```bash
# 使用 Babel 编译
pybabel compile -d i18n/locale -D messages

# 或使用 msgfmt
msgfmt messages.po -o messages.mo
```

**步骤 4: 重启服务**
```bash
python app.py --env=dev
```

### 3.3 批量提取待翻译文本

**使用 Babel 提取项目中的所有翻译文本**:
```bash
# 1. 提取所有 t() 包裹的文本
pybabel extract -F babel.cfg -o messages.pot .

# 2. 更新现有翻译文件
pybabel update -i messages.pot -d i18n/locale -D messages

# 3. 编辑 .po 文件添加翻译

# 4. 编译生成 .mo 文件
pybabel compile -d i18n/locale -D messages
```

## 4. 高级使用场景

### 4.1 带参数的消息翻译

**场景**: 消息中包含动态变量

```python
# 方式 1: 使用 Python 格式化字符串
username = "admin"
msg = f"用户 {username} 已被禁用"
return ResponseUtil.error(msg=msg)

# .po 文件
msgid "用户 admin 已被禁用"
msgstr "User admin has been disabled"
```

**更好的方式**: 使用占位符
```python
# 在翻译函数中支持参数
msg = t("用户 {username} 已被禁用", username=username)

# .po 文件使用占位符
msgid "用户 {username} 已被禁用"
msgstr "User {username} has been disabled"
```

### 4.2 在 Service 层使用翻译

**通常情况**: 在 Controller 层统一处理
```python
# Controller
try:
    await UserService.delete_user(user_id)
    return ResponseUtil.success(msg="删除成功")
except Exception as e:
    return ResponseUtil.error(msg="删除失败")
```

**特殊情况**: Service 层需要返回具体错误信息
```python
# Service 层
from i18n.translator import t

class UserService:
    @staticmethod
    async def delete_user(user_id: int):
        user = await UserDao.get_by_id(user_id)
        if not user:
            raise ValueError(t("用户不存在"))
        if user.status == "locked":
            raise ValueError(t("用户已被锁定，无法删除"))

        await UserDao.delete(user_id)

# Controller 层
try:
    await UserService.delete_user(user_id)
    return ResponseUtil.success(msg="删除成功")
except ValueError as e:
    return ResponseUtil.error(msg=str(e))  # 已翻译的消息
```

## 5. 常见问题 FAQ

### Q1: 翻译不生效怎么办？
**排查步骤**:
1. 检查请求头是否包含 `Accept-Language`
2. 确认 `i18n/locale/{language}/LC_MESSAGES/` 目录下有 `messages.mo` 文件
3. 确认 `.mo` 文件是从最新的 `.po` 文件编译的
4. 检查 ResponseUtil 是否正确使用 `t(msg)` 包裹消息
5. 重启服务确保加载最新翻译文件

### Q2: 如何添加新语言支持？
**步骤**:
```bash
# 1. 初始化新语言目录
pybabel init -i messages.pot -d i18n/locale -l ja_JP  # 日语

# 2. 编辑 i18n/locale/ja_JP/LC_MESSAGES/messages.po 添加翻译

# 3. 编译
pybabel compile -d i18n/locale -D messages

# 4. 在中间件中添加语言支持（如需要）
```

### Q3: 如何处理前端显示的静态文本？
**答**:
- **后端 API 响应**: 使用本文档描述的 `ResponseUtil` + `t()` 机制
- **前端界面文本**: 使用前端的 i18n 方案（如 Vue I18n）
- **数据库中的业务数据**: 考虑多语言字段设计（如 `name_zh`, `name_en`）

### Q4: 消息 ID 必须是中文吗？
**答**:
- **推荐**: 使用中文作为 `msgid`，因为中文是主要开发语言
- **替代方案**: 使用英文或自定义 key（如 `user.not.found`），但需额外维护映射
- **当前项目约定**: 使用中文消息作为 msgid

### Q5: 如何处理复数形式？
**答**:
使用 `gettext` 的复数支持：
```python
# .po 文件
msgid "{count} 个文件"
msgid_plural "{count} 个文件"
msgstr[0] "{count} file"
msgstr[1] "{count} files"
```

## 6. 最佳实践

### 6.1 消息编写规范
- ✅ 使用简洁明确的中文消息
- ✅ 避免消息中包含 HTML 标签
- ✅ 使用占位符而非字符串拼接
- ✅ 保持消息的通用性（避免过于具体）

**示例**:
```python
# ❌ 不推荐
msg = "用户" + username + "的密码已过期，请在2024年12月31日前修改"

# ✅ 推荐
msg = t("密码已过期，请及时修改")
```

### 6.2 翻译文件管理
- ✅ 定期同步 `.po` 文件到版本控制
- ✅ `.mo` 文件可选择性提交（或在部署时编译）
- ✅ 使用 `pybabel update` 而非手动添加新条目
- ✅ 翻译后进行 Review 确保准确性

### 6.3 性能优化
- `.mo` 文件在服务启动时加载，运行时查询速度快
- 避免在循环中重复调用 `t()` 翻译相同文本
- 考虑使用缓存机制（gettext 内置了缓存）
