# 项目架构规范 - 三层架构总览

## 元数据
- **分类**: 架构规范
- **标签**: 三层架构, FastAPI, SQLAlchemy, 项目结构
- **适用场景**: 了解项目整体架构, 新功能开发规划
- **相关文档**: Controller层职责, Service层职责, DAO层职责

## 架构概述

本项目采用经典的 **三层架构**（MVC 变体），基于 **FastAPI + SQLAlchemy** 技术栈。

```
┌─────────────────────────────────────────┐
│         Controller 层（控制器层）          │
│  - 接收 HTTP 请求                        │
│  - 参数验证                              │
│  - 调用 Service 层                       │
│  - 返回响应                              │
│  📁 module_admin/controller/             │
└─────────────────┬───────────────────────┘
                  │
┌─────────────────▼───────────────────────┐
│         Service 层（业务逻辑层）          │
│  - 业务逻辑处理                          │
│  - 数据校验（唯一性、权限等）            │
│  - 事务管理（commit/rollback）           │
│  - 调用 DAO 层                           │
│  📁 module_admin/service/                │
└─────────────────┬───────────────────────┘
                  │
┌─────────────────▼───────────────────────┐
│         DAO 层（数据访问层）             │
│  - 数据库 CRUD 操作                      │
│  - 使用 SQLAlchemy ORM                   │
│  - 不包含业务逻辑                        │
│  📁 module_admin/dao/                    │
└─────────────────┬───────────────────────┘
                  │
┌─────────────────▼───────────────────────┐
│         数据库 (MySQL/PostgreSQL)        │
└─────────────────────────────────────────┘
```

## 技术栈

- **后端框架**: FastAPI (Python ≥ 3.9)
- **ORM**: SQLAlchemy (异步模式)
- **数据库**: MySQL ≥ 5.7 / PostgreSQL
- **缓存**: Redis
- **认证**: OAuth2 + JWT

## 目录结构

```
ruoyi-fastapi-backend/
├── module_admin/           # 系统管理模块
│   ├── controller/         # 控制器层
│   ├── service/           # 服务层
│   ├── dao/               # 数据访问层
│   └── entity/            # 实体定义
│       ├── do/            # 数据库模型 (Data Object)
│       └── vo/            # 视图对象 (View Object)
├── config/                # 配置文件
├── sql/                   # SQL 脚本
└── utils/                 # 工具类
```

## 关键原则

1. **分层职责明确**: 每层只做自己该做的事
2. **异步优先**: 所有数据库操作都是 `async/await`
3. **事务管理**: 在 Service 层管理事务
4. **软删除**: 使用 `del_flag` 标记删除，不物理删除
5. **数据权限**: 在 Service 层处理数据权限校验

## 常见用户问题

**Q: 我要修改数据库某个字段，应该在哪一层写代码？**
A: 三层都要写 - DAO 层写数据库操作，Service 层写业务逻辑和事务，Controller 层定义 API 接口。

**Q: 能直接在 Controller 层操作数据库吗？**
A: 不能！必须通过 Service 层调用 DAO 层，保持分层清晰。

**Q: 为什么要用三层架构？**
A: 便于维护、测试、扩展；业务逻辑和数据访问解耦；团队协作更清晰。
