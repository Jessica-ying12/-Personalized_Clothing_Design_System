## 快速回答

**问题**: 如何在 Hammer-Admin 项目中实现分页查询和多表关联查询？

**答案**:
1. 使用 `PageUtil.paginate()` 统一处理分页
2. 通过 `is_page` 参数控制是否分页
3. 通过 `is_camel` 参数控制字段命名格式
4. 多表查询使用 `select(EntityA, EntityB).join()`
5. Service 层手动重组多表查询结果

## 1. 分页工具 PageUtil 详解

`utils.page_util.PageUtil.paginate` 是项目中查询列表的核心函数。

### 1.1 函数签名

```python
async def paginate(
    cls,
    db: AsyncSession,
    query: Select,
    page_num: int,
    page_size: int,
    is_page: bool = False,
    is_camel: bool = True
)
```

### 1.2 参数详解

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `cls` | `class` | 是 | 类方法标识（自动传入） |
| `db` | `AsyncSession` | 是 | 数据库会话对象，用于执行查询 |
| `query` | `Select` | 是 | SQLAlchemy 查询对象（未执行的 SQL 语句） |
| `page_num` | `int` | 是 | 当前页码，从 **1** 开始计数 |
| `page_size` | `int` | 是 | 每页记录数（如 10, 20, 50） |
| `is_page` | `bool` | 否 | **True**: 开启分页，返回 `PageResponseModel`<br>**False**: 不分页，返回完整列表 `List` |
| `is_camel` | `bool` | 否 | **True**: 字段名转为小驼峰 (camelCase)，适合前端<br>**False**: 保持数据库字段原样 (snake_case) |

### 1.3 返回值结构

#### 情况 1: 开启分页 (`is_page=True`)

返回 `PageResponseModel` 对象（类似字典结构）:

```json
{
  "rows": [
    { "id": 1, "userName": "admin", "status": "0" },
    { "id": 2, "userName": "user", "status": "1" }
  ],
  "total": 100,        // 总记录数
  "pageNum": 1,        // 当前页码
  "pageSize": 10,      // 每页大小
  "hasNext": true      // 是否有下一页
}
```

#### 情况 2: 不分页 (`is_page=False`)

直接返回**数据列表** `List`:

```json
[
  { "id": 1, "userName": "admin", "status": "0" },
  { "id": 2, "userName": "user", "status": "1" },
  { "id": 3, "userName": "test", "status": "1" }
]
```

### 1.4 字段命名转换 (`is_camel`)

**数据库字段** (snake_case):
```python
user_name, created_time, dept_id
```

**转换后** (`is_camel=True`):
```json
{
  "userName": "admin",
  "createdTime": "2024-01-01 10:00:00",
  "deptId": 100
}
```

**保持原样** (`is_camel=False`):
```json
{
  "user_name": "admin",
  "created_time": "2024-01-01 10:00:00",
  "dept_id": 100
}
```

## 2. 单表分页查询实战

### 2.1 完整示例：产品列表查询

#### DAO 层实现

```python
# module_hammer/admin/dao/product_dao.py
from sqlalchemy import select
from sqlalchemy.ext.asyncio import AsyncSession
from utils.page_util import PageUtil
from ..entity.do.product_do import Product

class ProductDao:
    """
    产品数据访问层
    """

    @classmethod
    async def get_product_list(
        cls,
        db: AsyncSession,
        query_object: ProductQueryModel,
        is_page: bool
    ):
        """
        查询产品列表

        Args:
            db: 数据库会话
            query_object: 查询条件对象
            is_page: 是否分页

        Returns:
            分页结果或完整列表
        """
        # 1. 构建基础查询
        query = select(Product)

        # 2. 添加查询条件
        if query_object.product_name:
            # 模糊查询
            query = query.where(
                Product.product_name.like(f'%{query_object.product_name}%')
            )

        if query_object.category_id:
            # 精确查询
            query = query.where(Product.category_id == query_object.category_id)

        if query_object.status:
            query = query.where(Product.status == query_object.status)

        # 3. 添加排序
        query = query.order_by(Product.created_time.desc())

        # 4. 调用分页工具
        return await PageUtil.paginate(
            db=db,
            query=query,
            page_num=query_object.page_num,
            page_size=query_object.page_size,
            is_page=is_page
        )
```

#### Service 层实现

```python
# module_hammer/admin/service/product_service.py
from sqlalchemy.ext.asyncio import AsyncSession
from ..dao.product_dao import ProductDao
from ..entity.vo.product_vo import ProductQueryModel

class ProductService:
    """
    产品业务逻辑层
    """

        cls,
        query_object: ProductQueryModel,

        db: AsyncSession
    ):
        """
        获取产品列表

        Args:
            query_object: 查询条件
            is_page: 是否分页
            db: 数据库会话

        Returns:
            产品列表（分页或完整）
        """
        return await ProductDao.get_product_list(db, query_object, is_page)
```

#### Controller 层实现

```python
# module_hammer/admin/controller/product_controller.py
from fastapi import APIRouter, Depends
from sqlalchemy.ext.asyncio import AsyncSession
from config.get_db import get_db
from utils.response_util import ResponseUtil
from ..service.product_service import ProductService
from ..entity.vo.product_vo import ProductQueryModel

router = APIRouter(prefix="/product", tags=["产品管理"])

@router.get("/list")
async def get_product_list(
    query_object: ProductQueryModel = Depends(),
    db: AsyncSession = Depends(get_db)
):
    """
    查询产品列表

    Args:
        query_object: 查询参数（自动从 query string 解析）
        db: 数据库会话

    Returns:
        产品列表响应
    """
    # 调用 Service 层
    result = await ProductService.get_product_list(
        query_object=query_object,
        is_page=True,  # 开启分页
        db=db
    )

    return ResponseUtil.success(data=result)
```

#### VO 层定义

```python

class ProductQueryModel(BaseModel):
```

## 3. 多表关联查询实战

在实际业务中，经常需要关联查询（Join），例如查询用户时同时获取部门信息。

### 3.1 典型案例：用户列表关联部门

**业务需求**: 查询用户列表时，同时返回用户所属部门的信息

**参考代码**: `module_admin/service/user_service.py` → `get_user_list_services`

### 3.2 DAO 层：多表 Join 查询

```python
# module_admin/dao/user_dao.py
from sqlalchemy import select
from sqlalchemy.ext.asyncio import AsyncSession
from utils.page_util import PageUtil
from ..entity.do.sys_user_do import SysUser
from ..entity.do.sys_dept_do import SysDept

class UserDao:
    """
    用户数据访问层
    """

    @classmethod
    async def get_user_list(
        cls,
        db: AsyncSession,
        query_object: UserQueryModel,
        is_page: bool
    ):
        """
        查询用户列表（关联部门）

        注意：select 中包含多个实体时，PageUtil 返回的每行是包含多个对象的元组
        """
        # 1. 构建多表查询（关键：select 同时选择多个实体）
        query = select(SysUser, SysDept).join(
            SysDept,
            SysUser.dept_id == SysDept.dept_id,  # Join 条件
            isouter=True  # 左外连接（即使部门不存在也返回用户）
        )

        # 2. 添加查询条件（只针对主表）
        if query_object.user_name:
            query = query.where(
                SysUser.user_name.like(f'%{query_object.user_name}%')
            )

        if query_object.dept_id:
            query = query.where(SysUser.dept_id == query_object.dept_id)

        # 3. 排序
        query = query.order_by(SysUser.create_time.desc())

        # 4. 分页（返回的 rows 每一项是 [SysUser对象, SysDept对象]）
        return await PageUtil.paginate(
            db=db,
            query=query,
            page_num=query_object.page_num,
            page_size=query_object.page_size,
            is_page=is_page
        )
```

### 3.3 Service 层：结果重组

**核心问题**: `PageUtil` 返回的多表结果需要手动重组为前端期望的 JSON 格式

```python
# module_admin/service/user_service.py
from sqlalchemy.ext.asyncio import AsyncSession
from utils.page_util import PageResponseModel
from ..dao.user_dao import UserDao
from ..entity.vo.user_vo import UserQueryModel

class UserService:
    """
    用户业务逻辑层
    """

    @classmethod
    async def get_user_list(
        cls,
        query_object: UserQueryModel,
        is_page: bool,
        db: AsyncSession
    ):
        """
        获取用户列表（含部门信息）

        核心：将多表查询结果重组为嵌套 JSON 结构
        """
        # 1. 调用 DAO 层查询
        query_result = await UserDao.get_user_list(db, query_object, is_page)

        # 2. 判断是否分页，分别处理
        if is_page:
            # 分页结果重组
            user_list_result = PageResponseModel(
                **{
                    # 保留分页元数据（total, pageNum, pageSize, hasNext）
                    **query_result.model_dump(by_alias=True),

                    # 重组 rows：将 [user_dict, dept_dict] 合并为嵌套结构
                    'rows': [
                        {
                            **row[0],           # 展开用户字典的所有字段
                            'dept': row[1]      # 将部门字典作为 dept 字段挂载
                        }
                        for row in query_result.rows
                    ],
                }
            )
        else:
            # 不分页结果重组
            user_list_result = []
            if query_result:
                user_list_result = [
                    {**row[0], 'dept': row[1]}
                    for row in query_result
                ]

        return user_list_result
```

**DAO 层返回**（`is_camel=True` 后的字典列表）:

## 4. 高级查询技巧

### 4.1 三表关联查询

**场景**: 查询用户 + 部门 + 岗位

```python
# DAO 层
query = select(SysUser, SysDept, SysPost).join(
    SysDept, SysUser.dept_id == SysDept.dept_id, isouter=True
).join(
    SysPost, SysUser.post_id == SysPost.post_id, isouter=True
)

# Service 层重组
user_list_result = [
    {
        **row[0],           # 用户
        'dept': row[1],     # 部门
        'post': row[2]      # 岗位
    }
    for row in query_result.rows
]
```

### 4.2 条件关联查询

**场景**: 只查询特定条件下的关联数据

```python
from sqlalchemy import and_, or_

# 复杂 Join 条件
query = select(SysUser, SysDept).join(
    SysDept,
    and_(
        SysUser.dept_id == SysDept.dept_id,
        SysDept.status == '0',  # 只关联正常状态的部门
        SysDept.del_flag == '0'
    ),
    isouter=True
)
```

### 4.3 聚合查询与分组

**场景**: 统计每个部门的用户数量

```python
from sqlalchemy import func

query = select(
    SysDept.dept_id,
    SysDept.dept_name,
    func.count(SysUser.user_id).label('user_count')
).join(
    SysUser, SysDept.dept_id == SysUser.dept_id, isouter=True
).group_by(
    SysDept.dept_id, SysDept.dept_name
)

# 注意：聚合查询通常不需要分页工具，直接执行即可
result = await db.execute(query)
data = result.all()
```

### 4.4 子查询

**场景**: 查询最近登录的用户

```python
from sqlalchemy import select

# 子查询：最近登录记录
subquery = select(
    func.max(LoginLog.login_time).label('last_login')
).where(
    LoginLog.user_id == SysUser.user_id
).scalar_subquery()

# 主查询
query = select(SysUser, subquery).where(
    subquery.isnot(None)  # 过滤没有登录记录的用户
)
```

## 5. 性能优化建议

### 5.1 避免 N+1 查询问题

**❌ 错误示例**（在循环中查询）:
```python
# Service 层
users = await UserDao.get_all_users(db)
for user in users:
    # 每个用户单独查询部门（N+1 问题）
    dept = await DeptDao.get_by_id(db, user.dept_id)
    user.dept = dept
```

**✅ 正确做法**（使用 Join）:
```python
# DAO 层直接关联查询
query = select(SysUser, SysDept).join(
    SysDept, SysUser.dept_id == SysDept.dept_id
)
```

### 5.2 合理使用索引

```sql
-- 为常用的 Join 字段添加索引
CREATE INDEX idx_user_dept_id ON sys_user(dept_id);
CREATE INDEX idx_dept_dept_id ON sys_dept(dept_id);
```

### 5.3 分页查询优化

**大数据量场景**: 使用游标分页而非 offset 分页

```python
# 传统 offset 分页（数据量大时性能差）
query = query.offset((page_num - 1) * page_size).limit(page_size)

# 游标分页（推荐）
query = query.where(User.id > last_id).limit(page_size)
```

### 5.4 只查询需要的字段

```python
# 只查询部分字段
query = select(
    SysUser.user_id,
    SysUser.user_name,
    SysDept.dept_name
).join(SysDept, SysUser.dept_id == SysDept.dept_id)
```

## 6. 常见问题 FAQ

### Q1: 分页查询返回的数据格式不对？
**A**: 检查 `is_camel` 参数设置，前端通常需要小驼峰格式（`is_camel=True`）。

### Q2: 多表关联查询后数据结构不符合预期？
**A**: `PageUtil` 不会自动合并关联对象，需要在 Service 层手动重组数据，参考用户列表查询的实现。

### Q3: 如何处理 Join 后的 NULL 值？
**A**:
1. 使用 `isouter=True` 进行左外连接
2. Service 层重组时检查 `row[1]` 是否为 None
```python
'rows': [
    {
        **row[0],
        'dept': row[1] if row[1] else None
    }
    for row in query_result.rows
]
```

### Q4: 分页总数不准确？
**A**:
- 确保 `PageUtil` 的 `query` 参数是完整的查询对象（包含所有 where 条件）
- 检查是否有 `group by` 导致计数不准

### Q5: 如何实现动态 Join？
**A**:
```python
query = select(SysUser)

# 根据参数决定是否 Join
if query_object.include_dept:
    query = select(SysUser, SysDept).join(
        SysDept, SysUser.dept_id == SysDept.dept_id
    )
```

## 7. 最佳实践总结

### 7.1 DAO 层职责
- ✅ 构建 SQLAlchemy 查询对象
- ✅ 处理查询条件、排序、Join
- ✅ 调用 `PageUtil.paginate()`
- ❌ 不处理业务逻辑
- ❌ 不重组数据结构

### 7.2 Service 层职责
- ✅ 调用 DAO 层查询
- ✅ 重组多表查询结果
- ✅ 处理业务逻辑
- ❌ 不直接操作数据库

### 7.3 分页参数规范
- 页码从 **1** 开始（不是 0）
- 每页大小建议范围：10-100
- 前端传参使用 `pageNum` 和 `pageSize`（小驼峰）

### 7.4 查询优化建议
- 优先使用 Join 而非多次查询
- 合理添加数据库索引
- 避免查询不需要的字段
- 复杂查询考虑使用缓存
